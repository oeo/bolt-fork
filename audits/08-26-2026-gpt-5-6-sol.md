## High Findings

```text
h1  src/core/transaction.ts:261-265, src/core/block-executor.ts:58-60  high: block transaction validity depends on validator wall clock; identical block bytes can change from invalid to valid over time. Validate transaction time against deterministic block context.

h4  src/network/sync-manager.ts:113-114,530-539,591-594  high: synchronization rejects valid higher-work forks deeper than 100 blocks or larger than sixteen maximum block bodies despite no checkpoints or finality. Add justified finality or bounded streamed reorganization.
h5  src/core/blockchain.ts:718-746,945-968  high: reorganization scans history and rebuilds state from genesis under chain-write lock. Valid mature-chain forks can stall node. Add ancestor snapshots, deltas, and indexed duplicate checks.
h6  src/core/block-executor.ts:12-17,48-84, src/core/blockchain.ts:267-273  high: valid zero-value block transfers can create unlimited accounts while each block copies, sorts, hashes, and rewrites full account state. Bound account creation and implement incremental authenticated state updates.
h7  src/network/sync-manager.ts:186-218,673-803  high: authenticated peers lack command work-rate budgets. Paced requests can force indefinite storage reads without overflowing message queues. Add per-peer command and work quotas.
h8  src/index.ts:250-445, src/core/fork-manager.ts:36  high: partial startup and shutdown do not own all services, listeners, or timers. Startup failure leaks resources and shutdown can leave process alive. Implement idempotent lifecycle rollback and owned handles.
h9  docs/architecture.md:61, tests/bats/smoke.bats:129  high: deployment lacks automatic startup integrity, backup/restore procedure, and abrupt-termination recovery gate. Add recovery ownership and SIGKILL/corruption tests.
h10 docker-compose.bats.yml:22-44, tests/bats/smoke.bats:76-137  high: deployment test uses one Docker bridge and internal DNS names, leaving cross-host discovery and routable endpoint behavior untested. Add routed multi-host equivalent coverage.
h11 src/core/mempool.ts:347-385  high: block selection repeatedly sorts all sender heads. A 10,000-sender bounded mempool required about 4.8 seconds synchronously. Replace repeated sorting with a priority queue.
```
